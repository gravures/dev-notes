# Phase 2: NAPI Bindings Extension - Research

**Researched:** 2026-09-01
**Domain:** NAPI-RS native bindings, Rust→TypeScript FFI
**Confidence:** HIGH

## Summary

Phase 2 extends the existing NAPI bindings in `awrit-native-rs/src/term.rs` to expose the Rust tmux utilities ported in Phase 1. The tmux branch's `term.rs` provides a complete reference implementation — four new functions (`isTmux`, `passthroughTmux`, `writeMaybeTmux`, `log`) plus modifications to `termEnableFeatures`/`termDisableFeatures` for extended-keys management. The changes are entirely additive to `term.rs` — no new files, no Cargo.toml changes, no module registration changes (lib.rs already re-exports `term::*`). The tmux branch uses NAPI-RS 3.0.0-alpha while we're on 3.2.4, but the `#[napi]` macro API is identical for these patterns.

**Primary recommendation:** Port the tmux branch's term.rs functions verbatim into the current term.rs, adapting only the import path (`crossterm::tmux::*`) and verifying the `#[cfg]` guards compile correctly.

## Architecture Patterns

### System Architecture Diagram

```
TypeScript (tmux.ts, tmuxProtocol.ts)
    │
    │  calls: isTmux(), passthroughTmux(), writeMaybeTmux()
    │  calls: termEnableFeatures(), termDisableFeatures()
    │
    ▼
awrit-native-rs/src/term.rs  (NAPI bindings layer)
    │
    │  #[napi] functions wrap Rust implementations
    │  uses crossterm execute! for stdout I/O
    │
    ▼
crossterm::tmux module  (Rust tmux utilities - Phase 1)
    │
    │  is_tmux(), tmux_escape(), TmuxBeginPassthrough, TmuxEndPassthrough
    │  TmuxSetExtendedKeysMode, TmuxMode
    │
    ▼
System stdout (terminal escape sequences)
```

### Pattern 1: NAPI Function Export

**What:** `#[napi]` proc macro exports a Rust function as a TypeScript-callable function. NAPI-RS automatically converts snake_case to camelCase.

**When to use:** Every Rust function that TypeScript needs to call.

**Example (from tmux branch reference):**

```rust
// Source: tmux:awrit-native-rs/src/term.rs
#[napi]
/// Returns true if called inside a Tmux session, false otherwise.
pub fn is_tmux() -> bool {
  crossterm::tmux::is_tmux()
}
```

NAPI-RS generates `isTmux(): boolean` in index.d.ts.

### Pattern 2: crossterm execute! for stdout I/O

**What:** Use crossterm's `execute!` macro to write ANSI sequences directly to stdout. This is the standard crossterm pattern — no buffering, no interleaving with console.log (which is suppressed in Awrit).

**When to use:** Any function that writes terminal escape sequences.

**Example (from tmux branch reference):**

```rust
// Source: tmux:awrit-native-rs/src/term.rs
#[napi]
/// Send the given sequence directly to the client terminal passing through tmux
pub fn passthrough_tmux(sequence: String) -> napi::Result<()> {
  execute!(
    std::io::stdout(),
    TmuxBeginPassthrough,
    Print(tmux_escape(&sequence)),
    TmuxEndPassthrough,
  )
  .map_err(|e| napi::Error::from_reason(e.to_string()))
}
```

### Pattern 3: Conditional tmux logic via is_tmux()

**What:** Check `crossterm::tmux::is_tmux()` at runtime to branch between tmux and non-tmux behavior.

**When to use:** `termEnableFeatures`/`termDisableFeatures` and `writeMaybeTmux`.

**Example (from tmux branch reference):**

```rust
// Source: tmux:awrit-native-rs/src/term.rs
pub fn write_maybe_tmux(sequence: String) -> napi::Result<()> {
  if is_tmux() {
    passthrough_tmux(sequence)
  } else {
    execute!(std::io::stdout(), Print(&sequence))
      .map_err(|e| napi::Error::from_reason(e.to_string()))
  }
}
```

### Pattern 4: Debug-only logging

**What:** `#[cfg(debug_assertions)]` gates the `log` function — only compiled in debug builds.

**When to use:** D-03 requirement for debug logging.

**Example (from tmux branch reference):**

```rust
// Source: tmux:awrit-native-rs/src/term.rs
#[cfg(debug_assertions)]
#[napi]
pub fn log(message: String) {
  crossterm::tmux::log(&message);
}
```

The underlying `crossterm::tmux::log` function has `#[cfg(all(unix, debug_assertions))]` guard.

### Anti-Patterns to Avoid

- **Don't create a separate file for tmux NAPI bindings** — D-01 explicitly puts everything in term.rs
- **Don't use `std::io::Write` directly** — use crossterm's `execute!` macro for terminal I/O
- **Don't add `#[cfg(unix)]` to NAPI functions** — the tmux branch doesn't gate NAPI exports on unix, only the underlying crossterm functions have `#[cfg(unix)]`

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Tmux detection | Custom env var check | `crossterm::tmux::is_tmux()` | Already ported in Phase 1 |
| ANSI escape wrapping | Manual string manipulation | `crossterm::tmux::tmux_escape()` | Handles ESC doubling correctly |
| DCS passthrough | Manual `\x1BPtmux;...\x1B\\` wrapping | `TmuxBeginPassthrough` + `Print` + `TmuxEndPassthrough` | Standard crossterm Command pattern |
| Extended keys protocol | Custom CSI sequence construction | `TmuxSetExtendedKeysMode(TmuxMode::Mode1)` | Handles all three modes correctly |

## Common Pitfalls

### Pitfall 1: Import path for tmux module
**What goes wrong:** Using `crossterm::tmux::*` when the module isn't re-exported at crate root.
**Why it happens:** Crossterm fork has `pub mod tmux;` in lib.rs — the module is accessible as `crossterm::tmux::`.
**How to avoid:** Use `crossterm::tmux::{is_tmux, tmux_escape, TmuxBeginPassthrough, TmuxEndPassthrough, TmuxMode, TmuxSetExtendedKeysMode}` exactly.
**Warning signs:** Compilation error: `could not find tmux in crossterm`

### Pitfall 2: Missing `style::Print` import
**What goes wrong:** Using `execute!` with a string without importing `crossterm::style::Print`.
**Why it happens:** The tmux branch uses `Print(tmux_escape(&sequence))` to write the escaped string via crossterm's Command trait.
**How to avoid:** Add `use crossterm::style::Print;` to the imports in term.rs.
**Warning signs:** Compilation error: `Print` not found or `execute!` macro cannot resolve the command type.

### Pitfall 3: #[cfg] guard mismatch
**What goes wrong:** The NAPI `log` function uses `#[cfg(debug_assertions)]` but the underlying `crossterm::tmux::log` uses `#[cfg(all(unix, debug_assertions))]`.
**Why it happens:** The NAPI function is called from TypeScript which is cross-platform, but the implementation is unix-only.
**How to avoid:** Use `#[cfg(debug_assertions)]` on the NAPI function — if it compiles on non-unix, the body simply won't execute because the crossterm function is guarded. Or gate the NAPI function with `#[cfg(all(unix, debug_assertions))]` to match.
**Warning signs:** Compilation warning or error on non-unix platforms.

### Pitfall 4: NAPI-RS version mismatch in reference
**What goes wrong:** Copying code verbatim from tmux branch which uses NAPI-RS 3.0.0-alpha while current is 3.2.4.
**Why it happens:** Different `#[napi]` macro behavior between versions.
**How to avoid:** The `#[napi]` and `#[napi(object)]` macros have identical behavior for these patterns across 3.0.0-alpha and 3.2.4. No changes needed.
**Warning signs:** Compilation errors related to NAPI macro expansion.

   - What's unclear: Whether the NAPI function should be cross-platform or unix-only.
